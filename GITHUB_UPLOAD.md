# Как выложить эту папку на GitHub

Это личная памятка, не часть научной записи. Она исключена из репозитория
(`.gitignore`, строка 129), поэтому в опубликованный проект не попадёт. Но учти:
`.gitignore` работает только при загрузке через `git`. Если перетаскивать папку
в веб-интерфейс GitHub, исключения не применяются и этот файл уедет вместе с
остальным — тогда просто удали его перед загрузкой.

## 1. Что публикуется

| | |
|---|---|
| Размер | 138 МБ, из них `runs/` — 136 МБ |
| Файлов | 1039 попадёт в коммит (в папке 1040: памятка исключена) |
| Самый большой файл | 11.8 МБ (`runs/kcsa_na-stride4/features/features.parquet`) |
| Лимиты GitHub | 100 МБ на файл — запас восьмикратный; предупреждение о размере репозитория начинается с 1 ГБ |
| Целевой адрес | `https://github.com/djeckins/PCM_diploma_project.git` (он же указан в `CITATION.cff` и в приложении диплома) |

Чего в папке нет: траекторий и топологий (ни одного `.xtc`, `.tpr`, `.top`,
`.gro`, `.pdb`) и таблиц покадровых координат `runs/*/coords/coords.parquet`
(468 МБ, пересчитываются шагом `coords`). Также удалены: мёртвые генерации
кэша моделей `runs/pooled-predict/*-v2.pkl` (их не читает текущий код) и
зеркала `runs/**/benchmark.csv` (дубликаты `benchmark.parquet`, 45 МБ, ни одна
строка кода их не читает — оба пересоздаются при прогоне). Всё остальное —
код, конфиги, тесты, документация, ноутбуки и артефакты прогонов — на месте.

Важно про конфиги: в публикуемой копии `configs/*.yaml` содержат условный путь
`/path/to/data`, а `configs/templates/*.yaml` — `${PCM2_DATA_ROOT}`. Ни то, ни
другое код сам не подставляет, поэтому **как есть конфиги не запустятся** — это
намеренно. Под конкретную машину они пересобираются командой
`python tools/init_configs.py`. Только **не запускай её в `pcm2-github`**: она
впишет твои реальные пути, и они уедут в публичный коммит. Пересобирать нужно в
рабочей папке `PCM 2`.

## 2. Предполётный чек-лист

Четыре пункта, которые стоит решить до того, как репозиторий станет публичным.

1. **Происхождение данных.** В `README.md` (раздел «Where the data came from») сказано, что траектории
   грамицидина A и MthK получены от научного руководителя в QMUL и используются
   с разрешения, без права распространения; KcsA и Cx43 взяты из публичных
   депозитов Zenodo (DOI проверены, лицензия CC-BY-4.0 у обоих). Проверь первую
   половину этого утверждения — по файлам проекта она не восстанавливается — и
   реши, называть ли руководителя по имени: сейчас в тексте стоит «the project
   supervisor», а строка ниже отправляет с вопросами «to the supervising
   laboratory», не уточняя, в какую.

2. **Формулировка в `src/pcm2/models/plsfma.py`, строка 9.** Там написано, что
   ядро — «a line-for-line port» процедуры PLS из `g_fma`. Фактически это
   независимая реализация опубликованной математики на NumPy, с тестом
   численной эквивалентности (`tests/test_plsfma_denham_core.py`, atol 1e-8) и с
   намеренным отличием в нормировке весов. Слово «port» — заявление о
   копировании из инструмента с неясными условиями, чего в коде нет. Возможная
   замена: «follows that tool's PLS conventions exactly — centering by training
   means only, no variance scaling, deflation of the residual of f only — but is
   implemented independently in NumPy from the published description; no g_fma
   source is copied.» Это твоё решение: фраза несёт ещё и научный смысл.

3. **Приватный или публичный.** Проще создать приватным, посмотреть, как всё
   выглядит на сайте, и открыть позже: Settings → General → Danger Zone →
   Change visibility.

4. **`CITATION.cff`.** Название диссертации и месяц сдачи там уже совпадают с
   титульным листом. Открытым остался один пункт — DOI архива Zenodo, если
   будешь его делать (см. раздел 6). Проверь ещё, что `repository-code`
   совпадает с адресом созданного репозитория:

```bash
grep -n "repository-code" CITATION.cff
```

Перед первым коммитом убери рабочий мусор:

```bash
cd "/Users/amgelina/Desktop/Учеба/Диплом/pcm2-github"
rm -rf .pytest_cache .ruff_cache .verify_tmp
find . -name __pycache__ -type d -prune -exec rm -rf {} +
find . -name '*.pyc' -delete
```

Быстрая проверка, что личных путей не осталось. Кроме самой этой памятки
найтись не должно ничего:

```bash
/usr/bin/grep -ral '/Users/amgelina' . | /usr/bin/grep -v GITHUB_UPLOAD.md
```

Путь `/usr/bin/grep` здесь не для красоты: в некоторых оболочках `grep` подменён
обёрткой, которая пропускает файлы из `.gitignore` и бинарники — то есть ровно
то, что здесь и надо проверить, — и тогда проверка «проходит» всегда. Убедиться,
что она вообще работает, можно на заведомом совпадении (число больше нуля):

```bash
/usr/bin/grep -c '/Users/amgelina' GITHUB_UPLOAD.md
```

## 3. Первый коммит

`git` установлен (`/usr/bin/git`, версия 2.50.1), но имя и почта для коммитов не
заданы — без них коммит не создастся. Сначала:

```bash
git config --global user.name "Angelina Ivanova"
git config --global user.email "djeckins@gmail.com"
```

Затем из этой папки:

```bash
cd "/Users/amgelina/Desktop/Учеба/Диплом/pcm2-github"
git init -b main
git add .
git status --short | head            # посмотреть, что попадёт в коммит
git commit -m "PCM 2: permeation-readiness monitor for ion channels — code, configs and run artefacts"
```

История публичного репозитория видна целиком — и автор, и тело сообщения.
Проверить, что в коммите стоит только твоё имя и нет посторонних служебных
строк (их иногда подставляют шаблоны и хуки):

```bash
git log --format='%an <%ae>' | sort -u
git log --format=%B | /usr/bin/grep -iE "^[a-z-]+-by:" \
  || echo "посторонних строк нет"
```

Первая команда должна вывести ровно одну строку —
`Angelina Ivanova <djeckins@gmail.com>`, вторая — «посторонних строк нет».

Ожидаемо: примерно 1070 файлов в коммите. Файлы из `.gitignore` (кэши,
`coords.parquet`, эта памятка) в список не попадут.

## 4. Создать репозиторий и запушить

`gh` (GitHub CLI) на этой машине не установлен, поэтому основной путь — через
сайт.

1. Открой <https://github.com/new>.
2. Имя репозитория — например `PCM_diploma_project` (именно оно сейчас указано в
   `CITATION.cff`). Описание можно взять первым абзацем `README.md`.
3. Выбери Private или Public.
4. **Ничего не добавляй**: ни README, ни `.gitignore`, ни лицензию — они уже
   есть в папке, иначе получится конфликт при первом push.
5. Create repository. GitHub покажет адрес вида
   `https://github.com/<логин>/PCM_diploma_project.git`.

Дальше в терминале:

```bash
git remote add origin https://github.com/<логин>/PCM_diploma_project.git
git push -u origin main
```

При первом push git спросит логин и пароль: в поле пароля нужен **personal
access token**, а не пароль от аккаунта. Токен создаётся в Settings → Developer
settings → Personal access tokens → Tokens (classic) → Generate new token, права
`repo`. Токен сохранится в связке ключей macOS (`credential.helper osxkeychain`),
второй раз спрашивать не будет.

Если предпочитаешь терминал целиком — `brew install gh` (Homebrew тоже не
установлен, сначала он), потом `gh auth login` и
`gh repo create PCM_diploma_project --private --source=. --push`.

Про время: ≈138 МБ уходят за минуту-две на домашнем интернете. Прогресс
git печатает сам. Если соединение оборвётся, повтори `git push` — он продолжит.

## 5. Почему не из рабочей папки «PCM 2»

В рабочей папке есть своя история git (`.git`, 106 МБ), и переносить её не стоит
по двум причинам: в ней лежат объекты пяти `coords.parquet` (≈467 МБ суммарно,
два файла по 169 МБ), а старые коммиты содержат неочищенные абсолютные пути с
твоим именем пользователя. История нужного качества из этого не получится без
перезаписи, поэтому здесь начинается чистая история с одного коммита.

Сама рабочая папка не тронута: 3 коммита, HEAD `62e1e3c`, все файлы на месте.

Старая история сохранена отдельно, если когда-нибудь понадобится:
`/Users/amgelina/Desktop/Учеба/Диплом/PCM2_old_history.bundle` (492 МБ).
Развернуть можно так:

```bash
git clone /Users/amgelina/Desktop/Учеба/Диплом/PCM2_old_history.bundle восстановленная-история
```

## 6. DOI на данные и на код (если нужно)

Для ссылки из диссертации на фиксированную версию:

1. На GitHub сделай release (Releases → Create a new release, тег `v1.0.0`).
2. Свяжи репозиторий с <https://zenodo.org> (Zenodo → GitHub → включить
   репозиторий), после чего каждый новый release получает свой DOI.
3. Полученный DOI впиши в `CITATION.cff` — там для этого оставлены две
   закомментированные строки (`doi:` и `date-released:`).

Депонировать сами траектории здесь нельзя: KcsA и Cx43 уже лежат в чужих
депозитах, на которые надо ссылаться, а грамицидин и MthK не твои для
распространения.

## 7. Если что-то пошло не так

| проблема | что сделать |
|---|---|
| push отклонён из-за размера файла | `git rm --cached <файл>`, добавить его в `.gitignore`, `git commit --amend`, снова push |
| перепутан адрес origin | `git remote set-url origin <правильный>` |
| нужно переделать первый коммит | `git reset --soft HEAD~1`, поправить, снова `git add`/`git commit` |
| в коммит попало лишнее | `git rm -r --cached <путь>`, дописать в `.gitignore`, `git commit --amend` |
| сделать репозиторий снова приватным | Settings → General → Danger Zone → Change visibility |
| push просит пароль каждый раз | проверь `git config --global credential.helper` — должно быть `osxkeychain` |
